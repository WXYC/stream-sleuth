# stream-sleuth

Live-stream song recognition for college radio. `recognizer.py` captures a few seconds of a station's Icecast stream with `ffmpeg`, identifies it with the unofficial Shazam client `shazamio`, and POSTs song changes to the station's API so live DJs get one-click "now playing" suggestions. WXDU runs it in production on an iMac (`run.sh`, `com.wxdu.stream-sleuth.plist`); its behavior must not change unless a PR says so on purpose.

## Layout

The code lives in the `stream_sleuth` package; `recognizer.py` is a thin shim that re-exports `parse`, `capture`, `post`, `identify_once`, `main`, and the settings constants, so `python recognizer.py` and WXDU's launchd job keep working.

| Module | Holds |
|---|---|
| `stream_sleuth/config.py` | The `STREAM_SLEUTH_*` settings (with `WXDU_*` aliases), read into module constants at import |
| `stream_sleuth/sources.py` | `Source` protocol; `IcecastSource`; `capture()` (ffmpeg); `FileSource` (a local file at an injected `Clock`'s offset, for replay; never a URL, not selectable from env) |
| `stream_sleuth/recognizers/base.py` | `Recognizer` protocol; `Identification` (exactly the four wire keys) and `EvalIdentification` (adds the harness's optional fields; two classes because `NotRequired` is 3.11+). `at` is seconds from the start of the hour file (the origin `plays.jsonl` uses); `ref_key` is the pool stage id (sha1 of the object key), not the object key; `source` is an `IdentificationSource`, `"shazam"` or `"local"`; `confidence` is recognizer-specific (Olaf `match_count`, absent for Shazam). `query_offset_s` and `ref_start_s` are set together, so `at + query_offset_s - ref_start_s` is the song's start; for Shazam the driver sets them to 0 and the response's `matches[0].offset`. Each field's contract is in its docstring. Nothing strips the extra fields: an `EvalIdentification` handed to an `Output` sends them too |
| `stream_sleuth/recognizers/shazam.py` | `ShazamRecognizer`; `parse()` and the `Shazam()` call |
| `stream_sleuth/recognizers/olaf.py` | `OlafRecognizer`: Olaf as a subprocess with the snapshot directory as `HOME` (and its own `.olaf/olaf_config.json`, so Olaf never falls back to a config beside its binary); `store()` via `olaf store --with-ids`; `parse_matches()` for `query --format json`; the strongest match at or above `min_match_count` (default 12, measured in Phase 1); an optional `lookup` maps an identifier to the wire keys; a query times out after `query_timeout_s` (60) so a hung Olaf cannot stall the loop. The snapshot must be absolute, not the home directory, and outside the checkout (`OlafError`); only `store()` creates one, and `recognize()` raises `OlafError` when the snapshot has no `.olaf/db/data.mdb` |
| `stream_sleuth/cli.py` | `python -m stream_sleuth.cli index build --home DIR PATH ID ...`; refuses (exit 2, one line) a `--home` that holds `results.jsonl` or whose `.lock` is held by a build or query run (a non-blocking `flock` probe, released at once and never creating the file). It checks those two file names only, mirrored as `SNAPSHOT_RESULTS` and `SNAPSHOT_LOCK` literals of `evaluation/olaf_snapshot.py`'s `RESULTS` and `snapshot_lock`, because the runtime package never imports `evaluation`; `tests/unit/test_cli_snapshot_guard.py` fails if they drift |
| `stream_sleuth/paths.py` | `CHECKOUT`, `inside_checkout()`, `DataPathError`, `require_outside_checkout()` (refuses a relative path or one inside the checkout, resolved by file identity), and `data_dir()` (the one place `STREAM_SLEUTH_DATA_DIR` and its default are resolved). `outputs.select_output()` uses `inside_checkout()` directly, for its setting-named messages; the Olaf snapshot (translated to `OlafError`), `corpus.write_plays`, `archive.fetch`/`fetch_all`, and `pool.stream`/`open_pool_db` call `require_outside_checkout()` |
| `stream_sleuth/outputs.py` | `Output` protocol; `HttpPostOutput`; `post()`; `JsonlOutput` (appends one UTF-8 JSON line per emission plus `emitted_at`; never truncates); `select_output()` picks one from `STREAM_SLEUTH_OUTPUT` and owns the refusal to run when it is incomplete |
| `stream_sleuth/loop.py` | the adaptive loop: `step()`, a pure `(state, result) -> (state, action)` function; `run()`, the driver that carries its decisions out against a `Source`, `Recognizer`, and `Output`; `identify_once()` and `main()` |

Each conforming class subclasses its protocol explicitly, so mypy checks its signatures. Sibling modules bind settings with `from .config import ...`, so a test that changes the environment must re-import the package; use `fresh_recognizer` (see Tests). `run()` takes an optional `sleep` and otherwise looks up `time.sleep` on every pause, so a patch of `time.sleep` is seen at call time. Change loop behavior in `step()` and test it there; `run()` only performs actions. The shim's names are copies of the package's bindings, not seams: patching `recognizer.post` (or assigning `recognizer.API_SECRET`) does not reach `main()`, so patch the `stream_sleuth` module that owns the call site. `Output.emit` takes a `Mapping[str, object]`, so a recognizer's `Identification` reaches an output without a cast.

## Interpreter

`requires-python = ">=3.10,<3.13"`, and `.python-version` pins 3.12.

- The floor is what `shazamio` enforces.
- The cap exists because `shazamio` pins `shazamio-core==1.1.2`, whose macOS wheels cover cp39–cp312 only, and because its dependency `pydub` imports `audioop`, which was removed in 3.13. A machine whose default `python3` is 3.13 or later cannot build WXDU's venv with `python3 -m venv venv`; use `uv`, which honors `.python-version`.
- WXDU's deploy runs `venv/bin/python recognizer.py` from `requirements.txt` and never pip-installs this package, so the cap cannot affect it.

## Install and checks

`uv.lock` is committed, and every install goes through it:

```sh
uv sync --locked --extra dev --extra eval
uv run ruff check .
uv run ruff format --check .
uv run mypy . --ignore-missing-imports
uv run pytest
uv run pytest -m "ffmpeg"   # needs a real ffmpeg on PATH
uv run pytest -m "olaf"     # needs ffmpeg and an Olaf build in STREAM_SLEUTH_OLAF_BIN
```

These are exactly the CI jobs; run them before every push. Do not document or use `pip install -e`, which drifts from the lock. `--locked` fails instead of silently rewriting `uv.lock` when `pyproject.toml` has changed; run `uv lock` deliberately and commit the result. `requirements.txt` is WXDU's install and is the one file not driven by the lock. It is not pinned (`shazamio>=0.8`), so a WXDU venv rebuild can pick up a newer `shazamio` than the lock tests.

## Tests

- `testpaths = ["tests"]`, `pythonpath = ["."]`. Every test directory has an `__init__.py`.
- pytest markers name **infrastructure CI must provision** (a binary, a service, an external API), following the org scheme in [`WXYC/wiki` `patterns/test-patterns.md`](https://github.com/WXYC/wiki/blob/main/patterns/test-patterns.md); `slow` is a cost dimension only. Directories say tier, markers say infrastructure.
- **A marker lands in the PR that adds the first test using it, never earlier**: declared in `pyproject.toml`, excluded in `addopts` as `not <marker>`, and given a same-named CI job, all at once. pytest exits 5 when a job collects nothing, so an empty job is a red build. The one exception is a manual-only marker that CI must never run, such as `external_api` (the real Shazam): it is declared and excluded in `addopts` with a `# ci-sync-skip: <marker> reason: …` comment above it, and has no test and no CI job. Do not remove it as a violation.
- CI quotes the expression, `pytest -m "<marker>"`; the marker-sync check only recognizes a quoted `-m` argument.
- The default CI job runs plain `pytest` and never names a subdirectory, so every unmarked test runs.
- `olaf` tests need ffmpeg too; they carry only the `olaf` marker, because the `olaf` job installs both and the `ffmpeg` job has no Olaf. Olaf is built from JorenSix/Olaf `a98d8c03cfd447011d402718ca2d10b2bb467eb0` with Zig 0.16.0 (`zig build -Doptimize=ReleaseFast`); the CI job adds `-Dcpu=baseline`, since its cached binary is restored on runners with other CPUs, and caches it keyed on that commit. Change the commit and Zig version in `OLAF_COMMIT` (`stream_sleuth/recognizers/olaf.py`, the one code constant, which a test checks against the other pins), the CI job's `env`, `pyproject.toml`'s comment, the README, and this file together. Olaf always runs with a snapshot directory as `HOME`, a `tmp_path` in tests, never `~/.olaf`. `fresh_recognizer` clears `STREAM_SLEUTH_OLAF_BIN`, so read it before calling the fixture.
- `stream_sleuth/config.py` reads every setting as `STREAM_SLEUTH_<NAME>`, falling back to its `WXDU_<NAME>` alias (a supported contract, never deprecated), into a module constant at import, and `recognizer.py` re-exports them. A test that sets the environment must delete every `WXDU_*` and `STREAM_SLEUTH_*` variable, remove `recognizer` and every `stream_sleuth*` entry from `sys.modules`, set its own values, and import afresh. Never `importlib.reload`. The `fresh_recognizer` fixture in `tests/conftest.py` does all of this; use it.
- Synthetic audio comes from `tests.audio.render(path, *segments, args=())`, the one place a test builds an ffmpeg `-f lavfi` command line (outside `tests/characterization/`, which may not be edited). A segment is a number of seconds of a 440 Hz sine or a `(source, seconds)` pair; two or more are concatenated. Output options go in `args`; a source that sets its own `d=` or `duration=` is refused with `ValueError`, as is a call with no segments.
- Fixtures are synthetic. Example artists are ones a freeform college station actually plays (Juana Molina, Jessica Pratt, Chuquimamani-Condori, Hermanos Gutiérrez), never mainstream ones.

## Characterization tests: what the refactor owes them

`tests/characterization/` pins WXDU's behavior against the unmodified `recognizer.py`, at four seams the refactor does not move: `shazamio.Shazam.recognize` patched on the class, a recording fake `ffmpeg` first on `PATH` (`tests/ffmpeg_stub.py`), a localhost ingest server as `WXDU_SHAZAM_API`, and `time.sleep` patched only for sentinel pause lengths (`WXDU_INTERVAL=1001`, `WXDU_INTERVAL_GAP=1003`), so `Popen.wait`'s own polling sleeps pass through. See `tests/characterization/conftest.py`.

Rules for every PR that restructures the recognizer:

- **No edits under `tests/characterization/`** in the refactor and station-neutral PRs. If a pin has to change, the behavior changed, and that is a separate PR that says so.
- `recognizer.py` keeps exporting `parse`, `capture`, `post`, `identify_once`, and `main` as module attributes.
- `parse()` keeps returning a plain `dict` with exactly `artist, song, album, label`, and `post()` keeps serializing whatever dict it is handed, unfiltered, with `json.dumps`' default ASCII escaping. No dataclass, no key filter.
- An injected sleep resolves `time.sleep` at call time; never bind it as a default argument at import, or the sentinel patch stops seeing the loop's pauses.

## The `plays.jsonl` boundary

The harness splits at two artifacts: a directory of hour-long audio files named by hour key, and `plays.jsonl`, one JSON record per logged play with `hour_key, play_id, t_offset_s, window_start_s, window_end_s, artist, title, album, era, pad_s, in_pool, pool_match_tier, pool_format, rotation, reorder_flag, play_order_status, carryover, track_rows, talk_rows, group, band, subset`. Offsets are seconds from the start of the hour file, and windows are clipped to `[0, 3600]`. `carryover: true` marks the previous hour's last track, written into each hour as an attribution candidate only: it never counts in a recall denominator; it repeats that play's `play_id`, so `play_id` is unique only within an hour.

The value sets are closed: `era` is `canonical` or `etl`; `play_order_status` is `single_writer`, `unreliable` (two writers, or no show to order within), or `etl`, and `reorder_flag` is a boolean only for `single_writer` (else `null`); `pool_match_tier` is `exact`, `fuzzy`, `title`, or `null`. `group`, `band`, and `subset` label the hour on every record, carryover plays included: `group` is `canonical-high`, `canonical-low`, `contrast`, or `null` (a `--hours` run has no selection to read it from); `band` is `overnight`, `daytime`, or `evening` (the hour key's own band when nothing labels it); `subset` is a boolean, true only for the four-hour subset and always false without a selection.

The plays CLI that writes these records (`--selection`, `--hours`, `--subset-only`, the `selection.json` checks and warnings, and the output-path checks) is described in the [README's Plays section](README.md#plays); the rules that build the join keys are under Name normalization below.

`in_pool` is `null` when the play has no artist to join on (empty after normalization), and `false` when no tier matched the keys it has; a key part that is empty after normalization (a missing tag) never matches. `pool_format` is the `pool.db` format (`mp3`, `aac`, `wav`, `flac`, or `mp4`) of the matched file, the first by object key at the winning tier, and `null` whenever `in_pool` is not `true`. A station producer writes these two artifacts, plus `selection.json`, the frozen selection record that `corpus select` writes. Modules downstream of them read nothing else, never a flowsheet, a database, or station-specific config: the scorer reads the two artifacts, and the leg runner (`evaluation/run.py`) reads only each hour key and its boolean `subset` from `selection.json`. Both it and `corpus.read_selection` parse the file through the station-neutral `evaluation/selection.py`'s `load_selection()`, which returns the whole record after the structural checks (UTF-8 JSON object, a non-empty `hours` object, each label an object with a boolean `subset`; one refusal line naming the file) and which `corpus` may import, never the reverse. That schema is a contract across the boundary: `tests/unit/test_corpus.py` checks that `run.read_hours` accepts what `select` writes, and `scan_for_station_imports` in `tests/import_scan.py` fails if any first-party module outside `tests/`, other than `evaluation/archive.py` and `evaluation/corpus.py`, imports either of those two.

## Name normalization (`evaluation/names.py`)

`evaluation/names.py` is station-neutral: it holds the tag-normalization rules (`fold`, `album_key`, `fuzzy`, `qualifiers`, `named_qualifiers`, `VERSION_QUALIFIERS`, `SAME_RECORDING`) that `corpus.PoolIndex` joins with, it is the one definition that a station's producer and the scorer can share, and it imports nothing from `evaluation.corpus` or `evaluation.archive` (`tests/unit/test_import_scan.py` checks it). It also holds the join's title-tier rule, so a scorer defines no key of its own: `title_keys(artist, title)` builds the `exact` and `fuzzy` title keys (a key with an empty part is left out), and `title_tier(play_artist, play_album, play_title, artists, album, title)` returns `exact`, `fuzzy`, or None for one play against one recording named by any of `artists` (a pool file passes its artist and album artist, an emission its one artist), including the version-qualifier test (`artists` is a tuple, never a bare string, which is a `TypeError`; the returned `exact` and `fuzzy` name the title keys that met, not `pool_match_tier`'s album tiers, where every title-key join is `title`). `PoolIndex` builds its title tiers through `title_keys`; its album tiers stay in `corpus.py`.

The cruft rules run first, on every key (the exact keys included): a featuring clause ("(feat. X)", "(ft. X)", "(with X)") always goes, and an edition clause (one led by "Deluxe", "Remastered", "Bonus", ..., or holding a "Deluxe", "Expanded", "Anniversary", "Bonus Track" or "Special" "Version" phrase anywhere in it) goes unless it names a different recording by a qualifier other than the generic "version", so "(Deluxe Version)", "(2011 Deluxe Version)" and "(Remastered 2011 Version)" join the plain name while "(Bonus Live Track)" does not. The exact keys see ASCII `(...)` and `[...]` clauses only; the fuzzy keys fold full-width brackets first, so a clause such as "（Remastered 2011 Version）" is cruft on the fuzzy keys alone, so an album logged with it joins at `fuzzy`, not `exact`. The fuzzy keys keep a version clause and drop every other bracketed clause (a translation, an edition, a radio edit).

A bracketed clause names a different recording when it has a whole version-qualifier word, plural and past forms included (`VERSION_QUALIFIERS` in `evaluation/names.py`: live, remix, demo, ...), outside any same-recording phrase (`SAME_RECORDING`: radio edit, album version, LP version, clean version, deluxe version, original mix, remaster, mono, edited, ...); "version" beside another qualifier adds nothing, so "(Live Version)" names what "(Live)" names, while a lone "(Alternate Version)" still names a different recording. On every tier (`exact`, `fuzzy`, `title`) a pool file joins a play only when the file's album or title names each qualifier that the play names in a bracketed clause of its album or title, so a play logged "(Live)" is in-pool only when the pool has that version. The pool file may name it outside brackets too: anywhere in its album ("Live at KEXP"), but in its title only after a spaced hyphen, en dash, or em dash ("Back, Baby - Live"), so a title like "Live Forever" names nothing; the play side reads only bracketed clauses. The fuzzy keys compare a qualifier by its stem, so "(Remix)" joins "(Remixed)".

A dotted initialism joins the same letters undotted, on the fuzzy keys only (a deliberate owner decision, WXYC/stream-sleuth#96): two or more single letters each followed by a period, the last period optional, key as one word before non-word runs become spaces, so "R.E.M.", "R.E.M" and "REM" share a fuzzy key and "A.R. Kane" keys as "AR Kane". The letters must touch their periods and stand at a word boundary (an underscore is a separator, so "_R.E.M." keys as "R.E.M."): a single initial ("J. Mascis"), initials spaced apart ("J. M. Barrie"), an abbreviation with a longer word ("St. Vincent", "Mr. Twin Sister", "Vol. 2", "No. 1"), a letter ending a longer word ("xa.b.c" keys "xa bc"), and a number ("v1.2", "1.5") key as before; a chain after a digit and a period still collapses ("1.A.B" keys "1 ab"). The same collapse runs where version words are read, so a dotted qualifier is the undotted one whichever side carries the dots: "(L.P. Version)" is the same-recording phrase "LP version" and "(L.I.V.E.)" names what "(Live)" names. The exact keys (`fold`, `album_key`) keep the dots, so such a pair joins at `fuzzy`, never `exact`. The rule lives only in `names.py`, so the join and `title_tier` pick it up together; a `plays.jsonl` written before it is never overwritten, so a rerun writes a new file.

Known gap on the `title` tier: it joins only when the play's title key equals the pool file's, so the version must sit in the title on both sides, keyed alike, or on neither; a play that misses for this reason is `in_pool: false`.

## Scoring (`evaluation/score.py`)

Station-neutral, and covered by the station import scan. It defines no name key: correctness is `names.title_tier` (the owner's decision on WXYC/stream-sleuth#20: the in-pool join's rules, not plain equality; so a dotted initialism joins the same letters undotted at `fuzzy`, "R.E.M." against "REM" included, per WXYC/stream-sleuth#96). It reads the stores only through `run.read_results`, which owns first-scoring-wins; it never calls `ResultStore.records()` or re-parses addresses itself, except to assign a stored key to a leg. Uncovered audio is never a miss: a play is in a recall denominator only when every address of the full-hour grid (`clips.grid` at 3,600 s) that starts in its window is in the leg's decoded grid and has a scoring record. A local (Olaf) emission names every artist tag its reference file carries (owner decision, WXYC/stream-sleuth#97): `attribute()` and `score_leg()` take an optional `references` mapping, `pool.reference_artists(db)` (stage id to the file's distinct non-empty `artist` and `album_artist`), and pass the emission's own artist plus the entry for its `ref_key` to `title_tier`, as the join does (the own artist stays, so a mapping from another `pool.db` never scores worse than none); `score.py` takes the mapping as an argument and does not import `evaluation.pool`; a caller that reads `pool.db` opens it with `pool.open_read_only()` (read-only, and its authorizer denies `ATTACH`; `PoolIndex.load` uses it too). No mapping, or a `ref_key` not in it, and the emission names its one artist; a Shazam emission always does, so its co-credit stays a near miss (WXYC/stream-sleuth#93). Both inputs are `run.Emission` and go through `attribute()`, so attribution, precision, and per-play scores run on one path; coverage does not (`score_leg` is the grid path and selects one capture length, while a replay file mixes them and the replay reports its own coverage). A replay record names its hour by its `address` field, never by the file it is in. The song start for time to first identification and lag is the earliest offset-bearing correct emission's, as Phase 1 measured the pads; do not switch it to a median. `pads()` recommends against the plan's fixed 180 s `DEFAULT_PAD_S`, never against `plays.jsonl`'s `pad_s` (the window pad the producer wrote, 220 s for WXYC's `etl` era), which it reports beside the recommendation.

## S3 and credentials

- **Every S3 client comes from `evaluation.s3_readonly`** (`archive_client()`, `pool_client()`), whose `before-call.s3` handler refuses any operation but `ListObjectsV2`, `GetObject`, and `HeadObject`. `tests/import_scan.py` enforces it over all first-party code: an AST scan forbids importing `boto3`, `botocore`, or `s3transfer` anywhere else, and a textual scan forbids S3 write and presign method names, touching a client's `meta.events` (which could remove the guard), and dynamic imports. Both scans walk every `*.py` in the repo except dot-directories and build output. The only exemptions are the factory and `tests/unit/test_s3_readonly.py`; do not add more. A test that needs a populated moto bucket seeds it with `seed_objects()` from that module, so every write call stays inside the exemption. Never add `awscrt` (`boto3[crt]`): its transfer client sends without botocore's events, so the guard would not see `upload_file` or `copy`; a test fails if it is installed.
- Guard tests use moto's `mock_aws`, never `botocore.stub.Stubber`, which answers before the guard runs and would make the tests pass without it. A test against a custom endpoint sets `MOTO_S3_CUSTOM_ENDPOINTS`, or moto lets botocore reach the real host.
- The harness reads `os.environ` only. Its settings live in `$STREAM_SLEUTH_DATA_DIR/eval.env`, outside the checkout, and are loaded into one process with `uv run --extra eval --env-file …` or a subshell, **never `source`d into an interactive shell**: `run.sh` exports its whole environment into the recognizer.

## Shazam

- **No test or manual check ever contacts Shazam.** `evaluation.shazam_eval.CountingClient` takes a required `base_url`; tests pass a localhost server's URL, and only the CLI passes `None` (the real host). Signatures are computed offline from synthetic audio, so tests run `Shazam.recognize` up to the HTTP request.
- `evaluation/shazam_eval.py` imports `stream_sleuth.paths` and `stream_sleuth.recognizers.shazam.parse`, and nothing else from the runtime package. `outcome_from()` takes the four wire fields (`artist`, `song`, `album`, `label`) from `parse()` so the study scores exactly what the deployed recognizer posts; the module adds only the match offset, and `tests/unit/test_shazam_eval_parity.py` fails if the two diverge. `parse` binds no runtime configuration at import (no `WXDU_*` or `STREAM_SLEUTH_*` reads). Its result store, throttle state, and work directory pass `require_outside_checkout()` before anything is created. The `external_api` marker is declared and excluded in `addopts` with a `ci-sync-skip` comment: CI never runs it, and no test uses it.
- **The recognizer identity is pinned.** `recognizer_identity(n)` is `shazam@<SHAZAMIO_VERSION>, segment=<n>`, built from the `SHAZAMIO_VERSION` constant in `evaluation/shazam_eval.py` (the way the Olaf identity is built from `OLAF_COMMIT`), never from the installed package. A live leg files every answer under `shazam@0.8.1, segment=12`, and a different string would make `run()` treat every stored address as never tried (re-spending the 500-per-day budget from the start) and make any reader that selects stored records by this identity find none of them. So `main()` of `shazam_eval` and of `evaluation/run.py` both call `require_pinned_shazamio()` first, before any path, lock, decode, or request, and exit when the installed `shazamio` is not the constant. A test pins the exact string and checks the constant against `uv.lock`'s `shazamio` and the installed version, so a `uv lock --upgrade-package shazamio` fails the tests. Change the constant only with the owner's go-ahead, in a PR that says the whole corpus will be queried again.
- Every request goes through `Throttle.acquire()` inside the client, so anything `shazamio` sends is counted, and it is counted in the state file before it is sent. Never construct `shazamio`'s default `HTTPClient` in the harness: it retries 429s up to 20 times.
- One process per throttle state file, enforced: a `Throttle` takes a non-blocking `fcntl.flock` on `<state>.lock` when constructed and holds it until `close()` (use it as a context manager), so a second opener, in this process or another, gets `ThrottleBusyError`. The state file is replaced atomically on every save, so never lock the state file itself. A test that simulates a restart closes the first `Throttle` before opening the next, and gives it the same clock: a restart whose clock runs more than the interval behind the state file's `last` is refused (`ValueError`), not slept on.
- `ResultStore.history()` is the one tally of scored keys, each tried key's latest status, and exhausted keys, shared by `run()` and the CLI's end summary; do not recompute them from `records()`. Day-stopping statuses (`STOP_REASONS`: 429 `rate_limited`, 403 `forbidden`) are never counted as an address's failures. The module sits at 300 of its 300 production lines (no blanks, comments, or docstrings): remove before you add. The budget variables are parsed by `evaluation/envvars.py` (`env_number`), a generic station-neutral helper; that is not a route around the ceiling for Shazam logic.
- `evaluation/run.py` runs the legs (a constant `LEGS` table whose `recognizers` name who runs each, hours from `selection.json` only) by calling `shazam_eval.run()` per Shazam leg inside one `Throttle` and `CountingClient`; it adds no second resume, retry, or budget mechanism. A Shazam leg that returns anything but `done`, or is `refused` (`FutureStateError`, caught per leg; the CLI then exits 1), leaves the later Shazam legs `not started`; Olaf legs still run, deliberately, since they spend no budget. `run_olaf` skips any address with a record under the identity (never a retry; Olaf is deterministic) and lets an `OlafError` abort the run. A run that selects no Shazam leg (`--only olaf`, or only Olaf-only legs) skips the shazamio pin check, `budget_from_env()`, the state path, and the throttle lock, and creates no `shazam/` directory; a run with any Shazam leg keeps the order pin, budget, paths, lock. `main()` runs the Shazam legs inside the `Throttle` and exits it before the Olaf legs run, so the state lock is never held through them; it checks the snapshot (one-line refusals) before taking that lock. A record `run_olaf` appends reads back through `read_results` as one emission (a `no_match` lands in `scored`, never `uncovered`). `OlafOutcome` subclasses `ShazamOutcome`, so an Olaf record carries Shazam's `offset_s` (always null) and `status` (`0`: the subprocess answered); its report keys are `<leg>/<recognizer>`. The Olaf store lives at `olaf/<snapshot>/results.jsonl`, and `evaluation/olaf_snapshot.py` guards it: no rebuild once it exists, no case-only twin of a snapshot name (`checked_snapshot_dir`), and `snapshot_lock` held by a build and by a query run. A build that returns normally writes the completion marker `<snapshot>/built.json` (Olaf commit, indexed and failed counts read from `pool.db`, and `source`) atomically (temp file + `os.replace`) under `snapshot_lock`, never when the build raises. A build writes the in-progress sentinel `<snapshot>/building` (atomically, under the lock) before it stores anything and removes it only after the marker is written, so a run and `--mark-built` both refuse a snapshot that has it, a stale marker notwithstanding, with a message that says to rerun the build. A build with `failed` files counts as complete, and every run logs the counts. `run.main` calls `require_built(home)` right after taking the snapshot lock, so a snapshot with no marker, an unreadable one, or one naming another `OLAF_COMMIT` is refused in one line before the Shazam throttle's lock. A snapshot built before markers existed is marked with `python -m evaluation.olaf_snapshot --mark-built NAME` (`mark_built`): under the lock, refusing if the sentinel or a marker exists or the Olaf index is missing, and (defensively; the build writes no such row) if `pool.db`, read through `pool.open_read_only`, has a row that is neither `indexed` nor `failed`; it writes only the new marker, and only a snapshot that predates the sentinel can reach it. Never hand-write a marker. It validates `selection.json` itself (a readable JSON object whose `hours` is a non-empty object, each `subset` a JSON boolean, at least one of them true) and never imports `evaluation.corpus`, which is WXYC-specific; the station import scan enforces that. Tests that call its `main()` fake `shutil.disk_usage`, so they never depend on the host's free space. The two budget variables are read by `shazam_eval.budget_from_env()` and nowhere else (a rate that is not a positive integer, or an interval that is not a finite number >= 0 (0 is allowed), exits with one line naming the variable, before any path, lock, decode, or request, in both CLIs); never give a leg its own state file, which would give it a second daily budget. Its read side is read-only: `read_results(stores, identities)` reads each store once (a `_Snapshot` hands `history()` the same records the emissions come from) and returns `Results(emissions, scored, uncovered)`. Emissions are the `matched` records under the requested identities, each with its store key and parsed address so legs at one offset stay distinct; `scored` is every key with a `matched` or `no_match` record; `uncovered` maps each tried-but-unscored key to its latest kind. Per key the first scoring record wins and a later one is logged and ignored. Which addresses were never tried needs the expected grid, which the scorer owns. `identities` is a set; a bare `str` raises `TypeError`, since `in` on a string is a substring test and Olaf identities nest (`min=1` inside `min=12`). A record under an identity outside the requested set (another match floor, or a shazamio version other than the pinned `SHAZAMIO_VERSION`) is counted per identity in one logged warning, never read as zero coverage. `scored` comes from `history()`; the first-scoring-wins guard applies the same `SCORING_KINDS` to the same snapshot.

## WXYC fork

This section applies to the `WXYC/stream-sleuth` fork and is dropped from anything offered upstream to `landmarco/stream-sleuth`.

- Every PR is created with `gh pr create --repo WXYC/stream-sleuth --base <base>`, so a stacked PR can never default to the upstream repo. Merge with rebase only.
- **`spike/` branches are local-only and are never pushed.** This fork is public.
- The `marker-sync` CI job calls `WXYC/wxyc-etl/.github/workflows/check-ci-marker-sync.yml@gha/v1`; read that repo's tag-stability policy before changing the call.
- `evaluation/archive.py` and `evaluation/corpus.py` are WXYC-specific: the first encodes the archive's Eastern-time hour keys and DST rules, the second the flowsheet's history (`ETL_STOP`, the August gap-import days, two-writer shows, the entry-type vocabulary, the per-era pads Phase 1 measured, and the 20-hour corpus: 16 `canonical` and 4 contrast hours, at most one contrast hour per broadcast (`show_id`) and per recurring slot (Eastern year, weekday, and hour of a show's first track row; a proxy for distinct programs, not a guarantee, and it does not identify DJs), and no talk-hour group, since WXYC plays music every hour and `talkset` rows are mic breaks inside music hours). `python -m evaluation.corpus select` freezes the selection into `hours.txt`, the four-hour `subset.txt` (2 high-share hours from different bands, 1 low-share, 1 contrast, each the top-ranked of its group), and a `selection.json` record; it never overwrites, so a later change to in-pool or the caps cannot silently move hours already spent on. They are the station side of the `plays.jsonl` boundary; everything else under `evaluation/` must stay station-neutral. `evaluation/names.py` is one of those station-neutral modules (see [Name normalization](#name-normalization-evaluationnamespy)).
- The viability-study plan lives in the private `wxyc-workspace` repo at `plans/stream-sleuth/plan.md`; the public summary is the epic, WXYC/stream-sleuth#1.
